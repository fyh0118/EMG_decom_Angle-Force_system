完整设计方案

登录界面 + 模式切换 + 系统框架搭建

方法选择

只有一个推荐方案：双窗口独立管理 — LoginScreen 和 MainApp 各自拥有独立的 uifigure，切换时关闭一个打开另一个。简单、清晰、低风险。

方案A：双窗口独立 ✅ 推荐

优点

  • 每个类独立管理自己的Figure生命周期
  • MainApp改动最小化
  • 切换时无需保存/恢复状态
  • 调试简单，互不干扰

缺点

  • 切换时有短暂的窗口闪烁
方案B：单窗口面板切换 ❌

优点

  • 无窗口闪烁

缺点

  • MainApp需要大幅修改来支持login/mode面板
  • 面板间状态管理复杂
  • 增加MainApp类的复杂度
  • 修改现有代码风险高

LoginScreen 类设计

职责显示登录界面，等待用户选择模式，返回选择结果
文件LoginScreen.m（根目录，不属于任何包）
公共方法mode = show() — 构建UI并阻塞等待用户选择，返回被选中的模式标识
阻塞机制使用 uiwait / uiresume 阻塞调用方
返回值"model_validation"、"rehab_assessment" 或空字符串（关闭窗口）

MainApp 修改点

# 位置 当前 改为
1 构造函数 MainApp() MainApp(mode)，存储到 Mode 属性
2 buildUI (窗口标题) 固定长标题 "肌电慧控 - 模型验证系统" 或 "肌电慧控 - 康复评估系统"
3 buildStatusBar 5列布局 6列布局：新增【返回登录】按钮（关闭图标的按钮，36px宽度，位于标题旁）
4 buildTabGroup 固定创建5个Tab model_validation → 3个Tab；rehab_assessment → 5个Tab
5 onClose 仅清理定时器 新增 ReturnToLogin 属性；点击返回或关闭窗口时设置属性

main.m 编排流程

function main()
    checkVersion();
    addAllPaths();

    while true
        login = LoginScreen();
        mode = login.show();   % 阻塞，直到用户选择

        if mode == ""
            break;             % 用户关闭了登录窗口 → 退出程序
        end

        app = MainApp(mode);
        app.launch();
        waitfor(app.getFigure());  % 阻塞，直到MainApp窗口关闭

        if ~app.ReturnToLogin
            break;             % 直接关闭窗口 → 退出程序
        end
        % ReturnToLogin = true → 回到登录界面
    end
end
