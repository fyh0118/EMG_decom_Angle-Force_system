核心设计决策：Tab 如何感知当前模式？

采集页和预测页在康复模式下需要不同的显示行为

问题

在康复评估系统中，数据采集页需要隐藏角度/力加载区，双输出预测页需要简化显示（去真实值、误差、指标）。Tab 需要知道自己处于哪种模式。

A

Tab 通过 MainApp.Mode 自行判断 ✅ 推荐

Tab 已有 MainApp 引用，直接读取 obj.MainApp.Mode。在 buildUI 中根据模式决定显示哪些组件。

Pros

  • 零构造函数改动
  • 遵循现有模式（Tab 已在读 MainApp 属性）
  • 改动量最小

Cons

  • Tab 内部多一个条件判断
B

修改 Tab 构造函数传入 mode

将 mode 作为第三个参数传入构造函数 AcquisitionTab(parent, mainApp, mode)

Pros

  • 显式参数传递

Cons

  • 破坏现有构造函数签名
  • MainApp 所有Tab创建处都要改
  • 两个系统的Tab实例不同但签名相同
推荐方案 A：在 AcquisitionTab 和 PredictionTab 的 buildUI() 中增加一行判断： 
isRehab = obj.MainApp.Mode == "rehab_assessment";
然后据此跳过或简化特定 UI 组件的创建。
